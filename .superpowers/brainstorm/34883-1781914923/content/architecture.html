Base de datos — tablas nuevas
users
  id          UUID  PK
  google_id   TEXT  UNIQUE
  email       TEXT
  name        TEXT
  lang        TEXT  default 'es'
  created_at  TIMESTAMP

players  (jugadores sincronizados — solo usuarios con cuenta)
  id          UUID  PK
  user_id     UUID  FK → users
  name        TEXT
  telegram_id BIGINT
  created_at  TIMESTAMP

game_rounds  (historial)
  id          UUID  PK
  user_id     UUID  FK → users  (NULL si sin cuenta — no se guarda)
  mode        TEXT
  difficulty  TEXT
  word_difficulty TEXT
  category    TEXT
  n_impostors INT
  sent        JSON  (lista de nombres)
  failed      JSON
  played_at   TIMESTAMP

saved_categories  (categorías favoritas del usuario)
  id          UUID  PK
  user_id     UUID  FK → users
  name        TEXT
  created_at  TIMESTAMP
Feature A — Gameplay improvements

word_difficulty — nuevo campo en StartGameRequest:

  • popular: palabras famosas (Messi, Coca-Cola, perro)
  • obscuro: palabras raras del nicho (jugador colombiano de 3ra división)

Categoría por ronda — el frontend ya puede mandar categories, solo falta conectarlo en la UI. Flujo:

  • Toggle "Categoría aleatoria" (default ON)
  • Si OFF: selector de categoría de la lista + opción "Proponer una"
  • Si propone una → POST /api/categories/validate → LLM la evalúa → si pasa, se usa

Impostores — en modo clásico, slider "N° de impostores" (1 a max jugadores/2)

Feature B — Tutorial Telegram ID

El Tutorial actual es texto plano. Mejora:

  • Pasos numerados con ícono del paso
  • Paso 2: enlace directo a @userinfobot en Telegram — reenvías cualquier mensaje y te dice tu ID
  • Código de ID resaltado visualmente ("Tu ID: 123456789")
  • Captura o diagrama inline (SVG) del flujo
Feature C — Historial de partidas

Dos niveles:

  • Sin cuenta: últimas 20 rondas en localStorage. Un drawer "Historial" en el header.
  • Con cuenta: histórico completo en DB, paginado, sincronizado entre devices.

Cada entrada muestra: fecha, categoría, modo, enviados ✅ / fallidos ❌.

Feature D — i18n (Español / Inglés)
  • Librería: react-i18next con namespaces por sección
  • Selector de idioma en el header (ES / EN) — persiste en localStorage (o en DB si hay cuenta)
  • Backend: categorías y mensajes de Telegram se envían en el idioma que manda el frontend (lang param)
  • LLM prompts ya son en inglés internamente — no cambia
Feature E — Google Ads
  • Script de AdSense en index.html (solo si VITE_ADSENSE_ID definido)
  • Componente <AdSlot /> — renders un banner solo si el usuario NO está autenticado
  • Slots: uno debajo del header, uno entre result y "Otra ronda"
  • Requiere que tengas el dominio aprobado por Google — el código se puede poner ya pero no muestra ads reales hasta aprobación
Feature F — Cuentas (Google OAuth)
  • Frontend: botón "Continuar con Google" → popup OAuth → recibe code → POST /auth/google → JWT
  • JWT guardado en localStorage, enviado en Authorization: Bearer header
  • Backend: authlib valida el Google token, crea/actualiza user en DB, devuelve JWT propio
  • Hook useAuth expone { user, login, logout, isLoading }
  • Hook usePlayers ya existe — cuando hay JWT, sincroniza con /users/players en vez de localStorage
Testing
  • Backend: pytest con mocks — auth middleware mockeable, DB en SQLite in-memory para tests
  • Frontend: Vitest + Testing Library para hooks y componentes críticos (useAuth, usePlayers sync, CategorySelector validation)
  • CI actualizado: ambos repos corren tests + lint en cada push
