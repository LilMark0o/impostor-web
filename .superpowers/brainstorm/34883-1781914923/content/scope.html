Scope del roadmap — ¿Qué construimos primero?

Hay demasiado para un solo spec. Identifiquemos los bloques y el orden.

Estado actual

Ya existe: 5 modos de juego, 3 dificultades de pista, envío por Telegram, jugadores en localStorage, UI básica. Lo que falta está abajo.

Features pedidas — agrupadas por subsistema
A

Gameplay improvements

• Dificultad de nicho (palabras raras vs. famosas)
• Escoger categoría cada ronda (o aleatoria)
• Proponer categorías propias + validación LLM
• Control de número de impostores
• Esfuerzo: medio — solo backend + UI form

B

Tutorial mejorado — cómo encontrar tu Telegram ID

• Pasos con capturas o diagrama
• Enlace directo a @userinfobot
• Actualmente existe como acordeón básico de texto
• Esfuerzo: bajo — puro frontend

C

Historial de rondas

• Log local (localStorage) de todas las partidas
• Ver categoría, modo, resultado, quiénes recibieron vs. fallaron
• Esfuerzo: bajo-medio — solo frontend

D

i18n — Español e Inglés

• Toda la UI en dos idiomas
• Selector de idioma persistido
• Las categorías y prompts del backend también bilingüe
• Esfuerzo: alto — toca todo

E

Google Ads (monetización)

• AdSense script + slots en la UI
• Solo para usuarios sin cuenta / free tier
• Requiere que el dominio esté aprobado por Google
• Esfuerzo: bajo de código, pero requiere dominio y aprobación

F

Cuentas de usuario opcionales

• Sign up / login para sincronizar jugadores entre dispositivos
• Sin cuenta = solo localStorage (ya funciona)
• Requiere backend auth + DB
• Esfuerzo: alto — cambia la arquitectura del backend

Selecciona los bloques que quieres en esta primera iteración del spec. Puedo hacer uno o varios, pero los más grandes (i18n, cuentas) merecen su propio spec.
